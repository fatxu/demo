This is the same problem space we've worked through before, but now with a pure KSH + AIX constraint and **no Python**. Let me lay out the optimal architecture.

---

## Constraint Analysis

| Resource | Value | Implication |
|---|---|---|
| vCPU | 12 | 12 parallel pipelines max |
| Network | 100 MB/s | ~360 GB/hr ceiling |
| Files | 5M × avg 1MB | 5 TB, small-file problem |
| Tooling | KSH + AWS CLI only | No boto3, no threading |
| Encryption | Must be in-shell | `openssl` is always on AIX |

**Core bottleneck**: 5M individual `aws s3 cp` calls → TLS handshake overhead will dominate. Each call costs ~50–200ms of overhead regardless of file size. At 1 call/file that's potentially **6–28 days** single-threaded.

**Solution**: Parallel workers + streaming pipeline + checkpointing.

---

## Architecture

```
File listing
    │
    ▼
split into N work-shards (1 per worker)
    │
    ├── Worker 0: openssl enc | aws s3 cp --  (streaming, no temp file)
    ├── Worker 1: openssl enc | aws s3 cp --
    ├── ...
    └── Worker 11: openssl enc | aws s3 cp --
    │
    ▼
checkpoint log (atomic append)
    │
    ▼
resume on failure (skip done files)
```

## The Script

```ksh
#!/usr/bin/ksh
# =============================================================================
# upload_encrypt.ksh — AIX 7.2, KSH, no external Python
# Parallel encrypt-stream-upload: openssl AES-256-CBC | aws s3 cp --
# =============================================================================

# ── CONFIG ────────────────────────────────────────────────────────────────────
SOURCE_DIR="/data/files"          # folder with 5M PDFs
S3_BUCKET="s3://your-bucket"
S3_PREFIX="encrypted"             # s3://your-bucket/encrypted/
WORKERS=12                        # match vCPU count
PASSPHRASE="your-strong-passkey"  # or use -kfile for key file
CHECKPOINT="/var/log/upload_done.log"
FAILED_LOG="/var/log/upload_failed.log"
WORK_DIR="/tmp/upload_shards"
LOG_DIR="/var/log/upload_workers"

# ── INIT ──────────────────────────────────────────────────────────────────────
mkdir -p "$WORK_DIR" "$LOG_DIR"
touch "$CHECKPOINT" "$FAILED_LOG"

# ── STEP 1: Build file list (skip already done) ───────────────────────────────
echo "[$(date)] Building file list..."
FILE_LIST="$WORK_DIR/all_files.txt"

ls "$SOURCE_DIR" | grep '\.pdf$' > "$WORK_DIR/raw_list.txt"

# Remove already-checkpointed files
# checkpoint format: one filename per line
sort "$CHECKPOINT" > "$WORK_DIR/done_sorted.txt"
sort "$WORK_DIR/raw_list.txt" > "$WORK_DIR/all_sorted.txt"
comm -23 "$WORK_DIR/all_sorted.txt" "$WORK_DIR/done_sorted.txt" > "$FILE_LIST"

TOTAL=$(wc -l < "$FILE_LIST")
echo "[$(date)] Files remaining: $TOTAL"

if [[ $TOTAL -eq 0 ]]; then
    echo "All files already uploaded. Exiting."
    exit 0
fi

# ── STEP 2: Shard file list across workers ────────────────────────────────────
# Split into WORKERS equal parts
split -l $(( (TOTAL + WORKERS - 1) / WORKERS )) "$FILE_LIST" "$WORK_DIR/shard_"

# ── STEP 3: Worker function ───────────────────────────────────────────────────
run_worker() {
    typeset worker_id=$1
    typeset shard_file=$2
    typeset log="$LOG_DIR/worker_${worker_id}.log"
    typeset ok=0 fail=0

    echo "[$(date)] Worker $worker_id started, shard: $shard_file" >> "$log"

    while IFS= read -r filename; do
        [[ -z "$filename" ]] && continue

        filepath="$SOURCE_DIR/$filename"
        [[ ! -f "$filepath" ]] && {
            echo "MISSING: $filename" >> "$log"
            continue
        }

        # S3 key: use MD5-prefix sharding to avoid S3 key hotspot
        # Extract numeric part from filename: pre1234567890last.pdf
        numpart="${filename#pre}"
        numpart="${numpart%last.pdf}"
        prefix2="${numpart:0:2}"   # first 2 digits as shard prefix

        s3_key="${S3_PREFIX}/${prefix2}/${filename}.enc"

        # ── STREAMING PIPELINE ──────────────────────────────────────────────
        # openssl reads plaintext → encrypts → aws s3 cp reads from stdin
        # No temp file, no disk I/O beyond the source read
        openssl enc -aes-256-cbc \
            -pbkdf2 \
            -iter 100000 \
            -pass "pass:${PASSPHRASE}" \
            -in "$filepath" \
            2>>"$log" \
        | aws s3 cp - "${S3_BUCKET}/${s3_key}" \
            --expected-size $(ls -l "$filepath" | awk '{print $5}') \
            --no-progress \
            2>>"$log"

        if [[ $? -eq 0 ]]; then
            # Atomic append to checkpoint (one line per file)
            echo "$filename" >> "$CHECKPOINT"
            (( ok++ ))
        else
            echo "$filename" >> "$FAILED_LOG"
            echo "FAILED: $filename" >> "$log"
            (( fail++ ))
        fi

        # Progress log every 1000 files
        (( (ok + fail) % 1000 == 0 )) && \
            echo "[$(date)] Worker $worker_id: ok=$ok fail=$fail" >> "$log"

    done < "$shard_file"

    echo "[$(date)] Worker $worker_id done: ok=$ok fail=$fail" >> "$log"
}

# ── STEP 4: Launch all workers in background ──────────────────────────────────
echo "[$(date)] Launching $WORKERS workers..."
pids=""
i=0
for shard in "$WORK_DIR"/shard_*; do
    run_worker $i "$shard" &
    pids="$pids $!"
    (( i++ ))
done

# ── STEP 5: Wait and collect exit codes ───────────────────────────────────────
all_ok=true
for pid in $pids; do
    wait $pid || all_ok=false
done

echo "[$(date)] All workers finished."
echo "Checkpoint entries: $(wc -l < "$CHECKPOINT")"
echo "Failed entries:     $(wc -l < "$FAILED_LOG")"

$all_ok && echo "SUCCESS" || echo "PARTIAL — check $FAILED_LOG"
```

## Key Design Decisions

### 1. Streaming pipeline — no temp files
```ksh
openssl enc -aes-256-cbc -pbkdf2 -in "$filepath" | aws s3 cp - s3://...
```
Encrypted bytes flow directly from `openssl` stdout → `aws s3 cp` stdin. Zero extra disk I/O. Critical on AIX where `/tmp` may be limited.

### 2. `--expected-size` on `aws s3 cp -`
When reading from stdin, AWS CLI can't seek to determine size for multipart decisions. Providing it pre-computed lets it choose the right upload strategy automatically.

### 3. S3 key prefix sharding
```
encrypted/12/pre1234567890last.pdf.enc
           ↑↑ first 2 digits of numeric part
```
Avoids S3 key-prefix hotspot throttling (3,500 PUT/s per prefix). With 2-digit prefixes you get 100 shards → well within limits.

### 4. Checkpoint + resume
```ksh
comm -23 all_sorted.txt done_sorted.txt > remaining.txt
```
On resume/crash, already-uploaded files are skipped instantly via `comm` (set difference on sorted files). Append-only log is crash-safe.

### 5. PBKDF2 key derivation
```
-pbkdf2 -iter 100000
```
Required on OpenSSL ≥1.1 to avoid deprecation warning, and makes brute-force attacks against the passphrase expensive. Use a key file (`-kfile /secure/key.bin`) instead of passphrase if security policy requires it.

## Throughput Estimate

| Factor | Value |
|---|---|
| Per-file overhead (TLS + S3) | ~100ms |
| Avg file processing time (1MB @ encrypt+upload) | ~300ms |
| Effective rate per worker | ~2–3 files/sec |
| 12 workers combined | ~24–36 files/sec |
| 5M files total | **~40–60 hours** |
| Network ceiling | 100 MB/s × 3600 × 60hr = **21.6 TB headroom** ✓ |

The bottleneck is **per-file TLS handshake overhead**, not bandwidth. 12 workers is the right multiplier to saturate the CPU without context-switch waste.

## Retry Failed Files

```ksh
#!/usr/bin/ksh
# retry_failed.ksh — reprocess only failed files
cp "$FAILED_LOG" "$WORK_DIR/retry_list.txt"
> "$FAILED_LOG"   # clear for fresh retry tracking

split -l $(( ($(wc -l < "$WORK_DIR/retry_list.txt") + WORKERS - 1) / WORKERS )) \
    "$WORK_DIR/retry_list.txt" "$WORK_DIR/retry_shard_"

i=0
for shard in "$WORK_DIR"/retry_shard_*; do
    run_worker "retry_$i" "$shard" &
    (( i++ ))
done
wait
```
